# dsh-tweaks

Набор твиков DeepSeek Harness. Каждый твик включается отдельно на странице Plugins,
поэтому лишнее можно выключить и не держать в интерфейсе.

| Твик | Что делает |
| --- | --- |
| `zoom` | Масштаб всего интерфейса: пара клавиш меняет размер интерфейса, а не только шрифт переписки |
| дальше | Перевод на русский и другое — по мере надобности |

## Клавиши

| Действие | Основной блок | Нумпад | Мышь |
| --- | --- | --- | --- |
| Крупнее | `Ctrl` + `=` | `Ctrl` + `+` | `Ctrl` + колесо вверх |
| Мельче | `Ctrl` + `-` | `Ctrl` + `−` | `Ctrl` + колесо вниз |
| Сброс 100% | `Ctrl` + `0` | `Ctrl` + `0` | — |

Shift не нужен: клавиша читается по позиции, поэтому `Ctrl` + `Shift` + `=` тоже
работает, и раскладка не важна. Шаг — 5%, диапазон — 50…200%. Размер показывается
плашкой в правом нижнем углу 1,2 с и хранится в `localStorage` (ключ `dsh.ui-zoom.v1`).

В браузере `Ctrl` + `=` / `-` / `0` забирает страница, поэтому там те же действия
доступны с `Alt`. Переназначить любую комбинацию: Settings → «Горячие клавиши».

## Установка

```
plugin_manager action=install_bundle target=<путь к папке плагина>
```

Вручную: добавить `"dsh-tweaks": "link:<путь>"` в зависимости профиля, вписать
`dsh-tweaks` в `dsh.profile.bundles`, затем `pnpm install` в папке профиля.

## Как устроено

* `client.js` — браузерная половина: значение масштаба, `zoom`, команды, плашка.
* `index.js` — хост-половина, пустая.
* `cordis.patch.yml` — вставки твиков: у каждой свой id и подписи (`meta.title`,
  `meta.description`), которые видно на странице Plugins.

Новый твик — отдельная вставка в `cordis.patch.yml` со своим id; тогда его можно
включить или выключить, не трогая остальные.

### Масштаб

`zoom` ставится корню приложения (`#root`). Размеры корня не подменяются: движок сам
отдаёт содержимому логическую ширину «ширина / масштаб», и интерфейс заполняет окно.
`transform: scale` не подходит — с ним расходится попадание курсора в элементы.

Настройку «Font size» в Settings плагин не трогает: она меняет только текст переписки.

### Попапы

Меню и подсказки приложение монтирует порталами в `body`, мимо корня. Общий `zoom` до них
не достаёт, поэтому каждый слой получает свой, а координаты плагин заворачивает в формулу:

```css
/* приложение пишет --dsh-ui-zoom-src-left: 270px */
left: calc(var(--dsh-ui-zoom-src-left) / var(--dsh-ui-zoom));
```

Делит браузер, а не JS. `--dsh-ui-zoom` лежит на корне документа, поэтому смена масштаба
пересчитывает все попапы разом. JS-деление давало дрейф: на нецелом масштабе частное —
периодическая дробь, браузер округляет inline-длину, и меню уезжало в разные места экрана.

`offsetWidth` и `offsetHeight` попапов плагин отдаёт приложению в вьюпортных пикселях:
по ним оно выравнивает меню по кнопке и подгоняет его под экран. При смене масштаба
плагин шлёт `resize` — якорь переехал.

### Меню по правой кнопке

Системное меню рисует Electron, и `zoom` до него не достаёт. Плагин перехватывает правый
клик и показывает своё: в поле ввода — `Undo`, `Redo`, `Cut`, `Copy`, `Paste`, `Select All`,
при выделении вне поля — только `Copy`. Вставка идёт через Clipboard API.

Фон меню — токены темы (`--dsw-alias-bg-overlay`, `--dsw-alias-bg-layer-2`). Подписи
берутся через `translate()`: штатный переводчик отдаёт сам ключ, если словарь не успел
подключиться, и в меню появлялось `menu.copy`.

### Полоски изменения ширины

Приложение прибавляет к ширине панели сдвиг `e.clientX - origin`, а ширина — в логических
пикселях. Курсор визуальный, поэтому плагин отдаёт событиям на полоске логический
`clientX`: иначе на 150% панель проходит в полтора раза больше курсора.

Позицию полоска получает как `left: viewport - rightbar`. Под `zoom` эта арифметика
расходится с сеткой — при 125% полоска стояла на 1078 px, а граница панели на 1202 px.
Поэтому плагин ставит полоску по границе колонки: `offsetLeft` и `offsetWidth`.

### Рамка интерфейса

`AppFrame` измеряет себя через `getBoundingClientRect()` и из этой ширины считает колонки.
Под `zoom` движок отдаёт визуальную ширину, поэтому плагин возвращает логическую. Ниже
1024 логических пикселей не опускает: по этому порогу приложение сворачивает сайдбар
(`SIDEBAR_AUTO_COLLAPSE`).

## Ограничения

* Меню `Application` и `Edit` рисует Windows — плагин до них не достаёт.
* Чем крупнее масштаб, тем раньше сворачивается сайдбар: `zoom` уменьшает логическую
  ширину, а порог у приложения — 1024 логических пикселя. При окне 1180 px панель
  сворачивается примерно со 120%.
* Ширина правой панели хранится в пикселях, поэтому с ростом масштаба занимает большую
  долю окна. Меняется перетаскиванием полоски.
* Вставка в своём меню зависит от доступа к буферу обмена.
* Длинное меню ограничивается по высоте в `vh`, а `vh` зум не масштабирует.

## Проверка

```powershell
node --check client.js
node test\check-client.cjs
```

`test/check-client.cjs` гоняет настоящий `client.js` в песочнице с заглушками DOM:
43 проверки — шаг и границы масштаба, хранилище, команды и их привязки, плашка,
`Ctrl` + колесо, попапы (перехват координат, `calc()`, сигнал `resize`, отсутствие
дрейфа), полоски, рамка и меню по правой кнопке.

`test/zoom-stand.html` открывается в браузере: прогоняет связку «якорь — портал» на всех
масштабах 0.5…2.0 и четырёх раскладках, отдельно проверяет полоску панели, перетаскивание
и меню под курсором.
